# @tayzu/catalog

The tenant-scoped software catalog: blueprints, properties, entities (with
`spec` and `status`) and relations. Global rules are in the root `CLAUDE.md`.
The behavior is specified in
`openspec/specs/catalog-core/spec.md`, and the design
is `design.md` next to it. When code and design disagree, stop and ask.

## Layers (`src/`)

- `domain/`: pure and I/O-free. Types, errors, context, identifiers, the
  meta-schema, entity validation, merge, compatibility and limits. No
  database, network, filesystem or telemetry calls; report through return
  values or callbacks. Most tests live here.
- `persistence/`: Drizzle table definitions (`schema.ts`) and repositories.
- `service/`: the operation pipeline (`pipeline.ts`) and the use cases.
- `api/`: the oRPC contract, the router and the error mapping.
- `telemetry/`: `contract.ts` (every span, metric, attribute and log event
  name) and the instruments.

Imports flow `api` → `service` → `persistence` and `domain`. `domain` never
imports from another layer.

## Operations

- Every service operation is declared with
  `defineCatalogOperation(name, handler)`. There is no second entry point.
- The `CatalogContext` (`tenantId`, `actor`, optional `actor.onBehalfOf`) is
  host-supplied and never part of a procedure's input schema.
  `contract:check` rejects any `tenantId` or `actor` field in the OpenAPI
  document.
- `actor.type` is data only (attribution and the reserved-identifier rule).
  Only `domain/reserved.ts` and `service/pipeline.ts` may compare it.
- Writes to reserved `_`-prefixed blueprints, and to their entities, are
  reserved to the `system` actor.
- Throw `CatalogError` with a stable `CATALOG_*` code, `issues` (JSON Pointer
  paths) and `details`. Unknown errors become `INTERNAL`, recorded only in
  sanitized form (type, SQLSTATE, constraint, and the stack without its
  message line).
- Cross-tenant access returns `CATALOG_NOT_FOUND`, exactly like a missing
  resource.

## Validation and data

- Blueprint definitions are meta-validated by strict Zod schemas (`.strict()`
  everywhere). No `$ref`, `$id`, `$defs`, `if`/`then`/`else` or nested object
  schemas.
- Entities are validated by Ajv on a schema _derived_ from the validated
  definition. Patterns go through the RE2 adapter (`re2js`, at most 512
  characters). `ajv-formats` runs in `fast` mode behind a 2048-character cap.
  `url` values allow only `http` and `https`.
- Parse untrusted input into null-prototype objects and reject `__proto__`,
  `constructor` and `prototype` at every depth. Check `CatalogLimits` (size,
  then counts) before validation or compilation.
- Relations are stored only as edges (`catalog_entity_relation`, `scope` is
  `spec` or `status`), never inside the `spec` or `status` JSON.
- Timestamps are UTC. Row IDs are UUIDv7 generated in the application.

## Telemetry

- Tracer and meter name: `@tayzu/catalog`. Depend on `@opentelemetry/api` and
  `@opentelemetry/api-logs` only. The SDK appears in tests only, through
  `@tayzu/observability`.
- Use only the names in `telemetry/contract.ts`, which mirrors the design's
  Observability contract. A new signal needs a design update first.
- Metrics carry only the allowed attribute keys. Entity identifiers and actor
  IDs are never metric attributes.

## API

- oRPC procedures with Zod input and output schemas. Tests call them
  in-process through `createRouterClient(router, { context })`. Never mount
  the router on an HTTP server before 002.
- `openapi/catalog.openapi.json` is generated by `pnpm contract:generate` and
  verified by `pnpm contract:check`. Never edit it by hand.

## Tests

- Unit tests (`*.test.ts`) sit next to the code. Integration tests
  (`*.int.test.ts`) cover `persistence`, `service` and `api` against a real
  PostgreSQL 16.
- Name tests after the spec scenarios that `tasks.md` quotes.
- Integration tests use a fresh random `tenantId` per test, and assert
  telemetry through the harness from `@tayzu/observability`.
