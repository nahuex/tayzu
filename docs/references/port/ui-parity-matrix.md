# Port UI parity matrix

The functional parity matrix that feeds `003-catalog-ui-core` and the later UI
changes (`010`, `011`, `012`, `013`, `014`, `018`, `019`, `020`, `030`, `034`).
It starts from [port-capability-inventory.md](port-capability-inventory.md): every
row of its sections 22 to 29 (Interface builder), plus every row elsewhere whose
Tayzu change is a UI change (`003`, `010`, `020`, and the UI-facing rows of
`005`, `012` and `013`).

## Sources and the ADR-0022 rule

Per [ADR-0022](../../adr/0022-port-public-sources-only.md), Port is studied only
through public sources and the human's own manual observations:

- **Public docs**: `docs.port.io`, read with plain HTTP GET only.
- **Open-source evidence**: two public Port repositories, shallow-cloned outside
  this repository and read as untrusted data, never executed.
  - **TF** = `port-labs/terraform-provider-port-labs` (the Terraform provider),
    license **Apache-2.0** (a `LICENSE` file with the Apache License 2.0 text
    sits at the repository root).
  - **PS** = `port-labs/port-plugin-sample` (the sample plugin), license **none
    found**: the repository has no `LICENSE` file and no `license` field in
    `package.json`. Treat it as all rights reserved: it is cited as facts about
    behaviour only, and no code is copied.
  - The repository named `terraform-provider-port` in the request does not
    exist under that name. The provider's public repository is
    `terraform-provider-port-labs`.
- **Demo observations**: written by the human, by hand, in a normal browser
  session, with
  [demo-observation-template.md](demo-observation-template.md).

Forbidden, for humans and agents alike: requesting, fetching, crawling or
automating anything on `demo.port.io`, `app.getport.io` or any other Port
product host; reverse engineering, CDP or HAR capture, bundle or source-map
analysis of Port; copying Port code, graphics, logos or other assets into this
repository. Open-source evidence below is described in our own words, with a
short identifier at most.

Parity here is functional. Tayzu's own design, code and visual identity
implement the behaviour; nothing in this file is a Port screenshot or a copy.

## How to read and fill the matrix

- **Docs checked**: every Port doc path was requested with `curl -I` against
  `https://docs.port.io<path>` on **2026-10-14** and returned HTTP 200, except
  the moved paths listed below. The inventory abbreviates paths (for example
  `/page/catalog-page.md`); this file gives the full current path from
  `https://docs.port.io/llms.txt`.
- **Moved paths** (the old or abbreviated form returned HTTP 404 on
  2026-10-14):
  - `/interface-builder/page/catalog-page.md` is now
    `/interface-builder/port-interface/page/catalog-page.md`. The other
    `page/*` docs live under the same `port-interface/page/` folder.
  - `/interface-builder/port-interface/dashboards/custom-widgets.md` is now a
    folder: `/interface-builder/port-interface/dashboards/custom-widgets/overview.md`,
    `.../built-in-widgets.md` and `.../custom-widget.md`.
  - The self-service docs for user inputs and forms live under
    `/workflows/build-workflows/triggers/self-service-trigger/`. The legacy
    `/workflows/actions-and-automations/create-self-service-experiences/` pages
    still resolve and are cited where the inventory cites them.
- **Observe in the demo**: a checklist for the human to follow by hand. Do it in
  a normal browser, note what you see, and do not capture traffic or inspect
  code.
- **Demo observation**: left empty on purpose. The human fills it with a short
  note or a reference to a session file made from the template (for example
  `session 2026-10-20, step 3`). Never paste Port text, assets or screenshots
  of Port into this file.
- **Tayzu status**: `built` only for changes `001`, `002` and `043`, and only
  when the capability is really implemented. Every row in this matrix is a UI
  capability, and none is implemented yet, so all are `planned`. Changes `001`,
  `002` and `043` deliver only the API and identity side of the mixed rows.
- Micro-options are grouped as in the inventory. Row ids are
  `<inventory section>.<n>`.
